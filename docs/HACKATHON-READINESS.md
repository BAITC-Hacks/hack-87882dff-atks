# Qoyma / SupplyMind: готовность к кейсу

Проверено 23.09.2026 по приложенному пакету HACKALEM AI.
**Полного соответствия ТЗ пока нет.** Работающий чат не заменяет расчёт закупок.

## Обязательные требования

| Требование | Состояние сейчас | Ограничение |
| --- | --- | --- |
| Продажи, остатки, товары в пути, категории, рост, сроки поставки | Частично: продажи, исторические остатки, транзит и кратность участвуют в расчёте | Нет связи с текущим MySQL-остатком, категориями, отдельным прогнозом роста и сроком поставки |
| Маусымдылық / сезонность и постоянный рост | Добавлен сезонный прогноз с годовым ростом; выбор метода по SKU на хронологической проверке | Сезонный метод требует истории; короткие ряды используют явно подписанный резервный метод. Прогноз роста из внешнего файла отдельно не подключён |
| Восстановление потерянного спроса при stockout | Исправлена передача corrected_demand в прогноз и закупку; проверена тестом | Месячный снимок не доказывает число дней дефицита. В текущих данных поддержанная историей поправка равна нулю; неизвестное не заменяется выдуманными продажами |
| Исключение крупных разовых продаж | Есть причинный месячный MAD/IQR-фильтр, тест на единичный всплеск | Нет идентификаторов клиентов и однозначной семантики транзакций; разовую покупку конкретного клиента подтвердить нельзя |
| Список SKU, поставщик, количество, объяснение, срочность; группировка | Есть количество, статус, объяснение, CSV и группировка отображения | Все внешние SKU пока в группе «Поставщик не указан». Это не выполненная реальная группировка по поставщикам |
| Проверка, изменение количества, подтверждение менеджером | Полный сценарий работает для операционного каталога MySQL, покрыт интеграционными тестами | Для внешних Python-результатов только просмотр; без согласованного сопоставления SKU/склада/поставщика подтверждение недоступно |
| Нельзя отправлять заказ автоматически | Выполнено | Ассистент не имеет инструментов изменения или отправки заказов |

## Что исправлено перед дедлайном

- Мобильные кнопки складов больше не растягиваются по вертикали.
- Ассистент работает с серверным `intelligence/.env`; корневой PHP-ключ и случайно унаследованные ключи не используются.
- Без ключа или при отказе провайдера есть явный «Локальный разбор, без OpenAI», без имитации ответа модели.
- Ответы на русском, с наименованием товара, проверенными цифрами и журналом выполненных инструментов.
- Веб-план экспортирует текущий отфильтрованный список в CSV; формулы в строковых полях экранируются для Excel.
- Метод расчёта, потери спроса за историю и сезонные факторы видны в подробностях веба и мобилки. Потери повторно не прибавляются к заказу.
- Исторические CSV пересчитаны. Excel и действующие складские остатки не изменены.

## Числа текущего снимка

724 товара в общем каталоге, 422 прогноза, 302 товара без прогноза,
21 позиция к пополнению, 25 с неполными входами.
44 прогноза используют сезонность с годовым ростом, 26 аналогичный месяц прошлого года,
72 CatBoost, остальные средние/резервные методы. Это не оценка точности.
Период прогноза: октябрь 2026. Остатки: снимки из файлов, не онлайн-склад.
Единицы разных товаров не суммируются в пользовательскую «общую потребность».

Методы выбирались по шести хронологическим месяцам. Отдельного отложенного теста,
гарантии точности и калиброванных доверительных интервалов пока нет.
Рост сезонной модели ограничен коэффициентом 0.5..2.0: это явное допущение алгоритма.

## Что нужно для полного замыкания процесса

1. Таблица соответствий внешний SKU → товар MySQL → склад → реальный поставщик, срок и условия поставки.
2. Согласованная семантика категорий и внешнего прогноза роста, единицы и дата действия.
3. API передачи текущих остатков/транзита/истории из MySQL в ML и сохранение версии входов.
4. Сохранение внешних рекомендаций как черновиков, редактирование менеджером и подтверждение с проверкой версии остатка. Готовую схему legacy approval можно переиспользовать после сопоставления.
5. Для точной проверки клиентских разовых заказов: обезличенный client_id и тип документа. Для stockout-дней: ежедневная доступность.

До появления этих данных безопаснее демонстрировать внешний расчёт и мобильные операции
как два явно подписанных источника, а не утверждать, что исторический файл является живым складом.

## Быстрая демонстрация

1. Открыть `http://localhost:8000/manager`, войти как менеджер, обновить результаты.
2. «Закупки» → «К закупке» → разбор IMT35180: нехватка 260, кратность 900, рекомендация 900.
3. Скачать CSV, показать пустые/неизвестные поставщика и сроки.
4. «AI-агент» → «Почему IMT35180 нужно закупить?». Режим ответа указан рядом.
5. В мобилке `http://localhost:8081` проверить компактный выбор склада и вкладку «Прогнозы».

Новый OpenAI-ключ добавляется в `intelligence/.env`, не в чат. Файл уже создан с пустым значением.
Ключ читается при каждом запросе; после добавления достаточно обновить результаты в веб-панели.
Платные запросы выполняются только при отправке вопроса с настроенным ключом.
